TypeScript lessons

TypeScript is JavaScript with types. You write the type of every value, and the compiler finds mistakes before the code runs. Big websites and apps use it because it keeps large code safe.

Hello, world

TypeScript code is turned into normal JavaScript by the compiler tsc, and then it runs in the browser or Node.js. Hello, world looks exactly like in JavaScript.

console.log("Hello, world!");
Output
Hello, world!

Every JavaScript program is also a valid TypeScript program. TypeScript only adds things on top: types, interfaces and checks. Files end with .ts.

The browser doesn't understand TypeScript directly. You run tsc file.ts, it checks the types and writes file.js, which you then run. In the browser you can try it at typescriptlang.org/play.

Line by line

console.log(...)print to the console, the same as in JavaScript.

Common mistakes

  • Trying to open a .ts file directly in the browser — first compile it to .js.

Try it yourself

Print your name and on the next line 2026.

Show answer 
console.log("Shiro");
console.log(2026);
Output
Shiro
2026

Variables with types

After the name of a variable you write a colon and the type: let age: number. Then TypeScript won't let you put text into it by mistake.

let userName: string = "Shiro";
let age: number = 18;
age = age + 1;
console.log(`${userName} is ${age}`);
Output
Shiro is 19

The three basic types are string (text), number (any number) and boolean (true/false). Write them in small letters.

You don't always need to write the type: let age = 18 is already a number for TypeScript. This is called type inference. Write types where they help the reader, for example in function parameters.

Line by line

let userName: string = "Shiro";a variable that can only hold text.
let age: number = 18;only numbers allowed.
`${userName} is ${age}`a template string, like in JavaScript.

Common mistakes

  • age = "nineteen" — error: Type 'string' is not assignable to type 'number'. That's TypeScript protecting you.
  • Calling a top-level variable name: browsers already have a global name, so TypeScript says Cannot redeclare block-scoped variable. Use another name, like userName.

Try it yourself

Create city: string and year: number and print: I live in Kyiv since 2020.

Show answer 
const city: string = "Kyiv";
const year: number = 2020;
console.log(`I live in ${city} since ${year}`);
Output
I live in Kyiv since 2020

Data types

Types can be combined. number | string means "a number or a string" — a union type. string[] is an array of strings.

let id: number | string = 42;   // union: number OR string
id = "A-42";
let tags: string[] = ["web", "ts"];
let done: boolean = false;
console.log(id, tags.length, done);
Output
A-42 2 false

A union type is useful when a value can really be one of several kinds, like an id that is sometimes a number and sometimes text.

There is also any — "anything goes". It turns type checking off, so use it only when you really must. A safer choice for unknown data is unknown: you must check the type before using it.

Line by line

let id: number | string = 42;id may be a number or text.
let tags: string[] = [...]an array where every item is text.
tags.lengthnumber of items: 2.

Common mistakes

  • tags.push(5) — error: a number can't go into a string[].

Try it yourself

Make an array scores: number[] with 3 numbers and print how many there are.

Show answer 
const scores: number[] = [5, 8, 10];
console.log(scores.length);
Output
3

Conditions

Conditions work like in JavaScript. A bonus: after typeof x === "number" TypeScript knows that inside this block x is a number.

function describe(x: number | string): string {
  if (typeof x === "number") {
    return "number " + x.toFixed(1);
  } else {
    return "text " + x.toUpperCase();
  }
}

console.log(describe(3));
console.log(describe("hi"));
Output
number 3.0
text HI

This trick is called narrowing. Before the if, x could be a number or a string, so you can't call number methods on it. Inside the if TypeScript has narrowed it down to a number, and in else it must be a string.

Use === and !== for comparisons, just like in JavaScript.

Line by line

typeof x === "number"check the type while the program runs.
x.toFixed(1)a number method: 1 digit after the dot.
x.toUpperCase()a string method: capital letters.

Common mistakes

  • Calling x.toUpperCase() before checking the type — error, because x might be a number.

Try it yourself

const t: number = 30. Print "Hot" if t > 25, otherwise "OK".

Show answer 
const t: number = 30;
if (t > 25) {
  console.log("Hot");
} else {
  console.log("OK");
}
Output
Hot

Loops

for ... of goes through every item of an array. The classic for with a counter works too.

const langs: string[] = ["TS", "JS", "Go"];
for (const lang of langs) {
  console.log(lang);
}

for (let i = 0; i < 3; i++) {
  console.log("Step", i);
}
Output
TS
JS
Go
Step 0
Step 1
Step 2

Inside for (const lang of langs) TypeScript knows that lang is a string, because langs is a string[]. You get autocomplete and checks for free.

Don't mix up for ... of (values) with for ... in (keys/indexes) — for arrays you almost always want of.

Line by line

for (const lang of langs)lang is each item in turn.
for (let i = 0; i < 3; i++)a counter from 0 to 2.

Common mistakes

  • Using for (const x in arr) and getting "0", "1", "2" instead of values.

Try it yourself

Print the numbers from 1 to 5.

Show answer 
for (let i = 1; i <= 5; i++) {
  console.log(i);
}
Output
1
2
3
4
5

Functions

In TypeScript you write the types of parameters and of the result. Then nobody can call the function with wrong values.

function add(a: number, b: number): number {
  return a + b;
}

const greet = (name: string): string => `Hello, ${name}!`;

console.log(add(2, 3));
console.log(greet("Shiro"));
Output
5
Hello, Shiro!

The type after the brackets ): number is the type of the result. If the function returns nothing, write : void.

A parameter can be optional with ?: function hi(name?: string), or have a default value: function hi(name = "friend").

Line by line

function add(a: number, b: number): numbertwo numbers in, a number out.
(name: string): string => ...an arrow function with types.

Common mistakes

  • add("2", 3) — error: a string is not a number. In plain JavaScript this would silently give "23".

Try it yourself

Write square(n: number): number and print square(7).

Show answer 
function square(n: number): number {
  return n * n;
}
console.log(square(7));
Output
49

Interfaces

An interface describes the shape of an object: which fields it has and their types. ? marks a field that may be missing.

interface User {
  name: string;
  age: number;
  email?: string;   // ? = optional
}

const user: User = { name: "Shiro", age: 18 };
console.log(user.name, user.age);
console.log(user.email ?? "no email");
Output
Shiro 18
no email

Objects are everywhere in web apps: users, products, messages. An interface is a contract: every User must have a name and an age. If you forget a field or misspell it, TypeScript tells you at once.

?? means "if the left side is missing (null or undefined), use the right side".

Line by line

interface User { ... }describe what a user looks like.
email?: string;email may be absent.
user.email ?? "no email"use the text if there is no email.

Common mistakes

  • { name: "Shiro" } without age — error: Property 'age' is missing.

Try it yourself

Make an interface Product with title: string and price: number, create one and print its title.

Show answer 
interface Product {
  title: string;
  price: number;
}
const p: Product = { title: "Book", price: 12 };
console.log(p.title);
Output
Book

Mini project: to-do list

Everything together: an interface for a task, a typed array, a function that adds tasks and a loop that prints them.

interface Task {
  title: string;
  done: boolean;
}

const tasks: Task[] = [];

function addTask(title: string): void {
  tasks.push({ title, done: false });
}

addTask("Learn TypeScript");
addTask("Build a site");
tasks[0].done = true;

for (const t of tasks) {
  console.log((t.done ? "[x] " : "[ ] ") + t.title);
}
Output
[x] Learn TypeScript
[ ] Build a site

This is the core of any to-do app. Task[] means "an array of tasks". { title, done: false } is a short form of { title: title, done: false }.

condition ? a : b is a short if: if done, take "[x] ", otherwise "[ ] ". In a real app the same code would draw the list on the page.

Line by line

const tasks: Task[] = [];an empty array that will only hold tasks.
function addTask(title: string): voidadds a task, returns nothing.
t.done ? "[x] " : "[ ] "choose the mark by done.

Common mistakes

  • tasks.push({ title }) without done — error: Property 'done' is missing.

Try it yourself

Add a function countDone(): number that returns how many tasks are done, and print it.

Show answer 
interface Task {
  title: string;
  done: boolean;
}

const tasks: Task[] = [
  { title: "Learn TypeScript", done: true },
  { title: "Build a site", done: false },
];

function countDone(): number {
  return tasks.filter((t) => t.done).length;
}

console.log(countDone());
Output
1

Quiz

5 questions. Pick an answer to see if it is right.

1. What will this code print?

let a: number = 5;
a = a * 2;
console.log(a);

a was 5, then multiplied by 2.

2. What happens here?

let age: number = 18;
age = "18";

A number variable can't hold text — the compiler stops you.

3. What does number | string mean?

| is a union: the value is one of these types.

4. Which mark makes an interface field optional?

interface User {
  email___: string;
}

email?: string means the field may be missing.

5. What will this code print?

const nums: number[] = [1, 2, 3];
nums.push(4);
console.log(nums.length);

push added one more item.
